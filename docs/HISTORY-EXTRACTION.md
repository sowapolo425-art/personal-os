# 跨 Agent 历史提取与分析 · v0.4

用户在自己使用的 Agent 中发出任务。由该 Agent 读取它能访问的历史对话，
通过统一 MCP 保存到用户自己的资料库。多个客户端使用同一个 `--vault` 绝对路径。
Personal OS 不扫描其他软件、不扩大聊天访问权限、不调用模型 API，也不提供托管。

## 使用流程

1. 按 [Agent 接入指南](AGENTS.md) 连接本地 stdio MCP；面板与各 Agent 使用同一个资料库。
2. 面板打开“跨 Agent 记忆”，复制提取任务，在你使用的软件中发送。
3. Agent 分批提交原文，再提出有来源依据的结论草稿。
4. 面板查看已提交会话、消息和提取状态；在“待确认草稿”核对结论及原文，批准或拒绝。
5. 在其他软件重复以上步骤。再次整理时，Agent 查看进度并处理新增或修改消息。
6. 后续使用任意可接入 MCP 的 Agent 检索分析；或选择资料导出分析包，交给自己的模型 API 程序。

**已提交会话数不等于软件历史总数。** 客户端是否能读取其他会话，需要客户端自身支持。
只能访问当前会话时就只提交当前会话，不能模拟读取其他会话。若只能导出文件，可使用现有导入功能。
当前未实现各品牌历史目录的专用扫描器，也未完成 Codex、Claude Code、ZCode、WorkBuddy 的实际全历史读取验收。

## 统一 MCP 契约

原有四个工具继续保留。新增七个工具如下：

| 工具 | 作用 |
|---|---|
| `ingest_conversation` | 分批保存 user/assistant 原话，记录结构化来源并跳过重复提交 |
| `list_conversations` | 返回已保存会话、最新消息 ID、指纹和提取进度 |
| `propose_insight` | 提交背景、偏好、目标等结论草稿，要求证据 ID 和结论类型 |
| `mark_conversation_processed` | Agent 提取完成后的进度检查点，拒绝过期指纹 |
| `prepare_analysis` | 返回指定记录的可携带分析包，不调用外部模型 |
| `list_extraction_sources` | 查询上传文件、思考与事务的原文及提取进度 |
| `mark_source_processed` | 记录单份原始资料的提取检查点，拒绝过期内容 |

MCP 提示词 `extract_history` 提供完整任务规则；服务 instructions 也包含规则，
不依赖客户端必须支持提示词菜单。面板复制按钮只是复制任务，不会启动或控制其他软件。

## 上传文件、日常思考和事务

这些都是原始资料入口，不限于历史聊天：

1. 面板“导入历史资料”选择 UTF-8 MD/TXT、文字 PDF、DOCX 或对话 JSON，预览后保存。
2. 面板“记录想法或事务”直接输入原话，选择思考、经历事件、目标、项目等类型；也可以让 Agent 用 `capture_record` 保存授权原文。
3. “跨 Agent 记忆”显示文件和日常资料的提取状态；复制“资料提取任务”交给你的 Agent。
4. Agent 使用 `list_extraction_sources`、`read_record` 读取资料，调用 `propose_insight` 生成草稿，并通过 `mark_source_processed` 记录进度。

MCP 提示词 `extract_materials` 与服务 instructions 提供统一规则。上传和输入只是保存，
不会在后台自动运行其他软件的 Agent。用户仍在自己使用的 Agent 中发起提取任务。
已确认结论可被后续分析读取，但不作为待提取原文反复进入这个清单。

PDF 最多 200 页，仅提取已有文字；DOCX 仅提取正文/表格段落文字，不执行宏或字段代码。
扫描 PDF、图片、表格工作簿、音视频等尚未内置解析，可由有相应能力的 Agent 先读取，
再保存明确授权的摘录及来源。单文件上限 8 MB；正文较长的 PDF/DOCX 会拆成片段。
原文件、嵌入附件和图片不复制到资料库，保留的是提取文字与文件名来源。
文件里的说法或人物不自动当作用户事实；混合导入资料作为分析来源，而非直接的用户陈述证明。

同文件名和正文重复提交会跳过；不同文件名即使正文一样也保留独立来源。
系统不会推断两个文件是否属于同一个真实来源。资料版本变化后，旧提取检查点失效。

### 提交原文

```json
{
  "agent": "my-agent/workspace-a",
  "conversation_id": "stable-session-123",
  "title": "虚构示例：学习计划",
  "messages": [
    {"message_id": "msg-001", "role": "user", "content": "我想每周读一本书", "timestamp": "2026-10-10T10:00:00+08:00"},
    {"message_id": "msg-002", "role": "assistant", "content": "可以先制定阅读计划"}
  ],
  "sensitivity": "private"
}
```

任意 Agent 名称都可使用；不同账号/工作区要使用不同且稳定的命名空间。
会话和消息 ID 必须稳定，不要每次随机生成；无法提供 ID 时，客户端自行生成稳定标识并持续复用。
每批 1–200 条、单条正文最多 100,000 字符、合计最多 1,000,000 字符。
仅文字 user/assistant 消息，时间作为原始来源字段保存，不自动推断其真实性。

同软件、会话、消息 ID、角色、时间与原文完全相同则返回已保存 ID；
消息编辑后保留新旧版本，最新已保存版本进入会话摘要。重放旧批次不会覆盖新版本。
不同软件即使文字相同也保留独立来源；语义相同的结论由 Agent 检索后合并为更新草稿，
不会仅凭文字相同就抹掉不同来源，也不宣称已经实现自动语义去重。
分批写入不是跨文件事务，异常中断可重复提交，已成功写入的消息会被跳过。

`private` 允许接入该资料库的 Agent 读取；`restricted` 默认不暴露。
受限来源产生的草稿继承受限级别。一段会话含受限消息时，默认会话列表隐藏整段会话，
避免把可见片段误报成完整提取。需要访问时，由用户明确为对应 MCP 服务添加 `--allow-restricted`。
已有会话含受限消息时，后续批次继承受限级别。重复提交不会修改已保存消息的可见性。

### 提取结论

`propose_insight` 要求 `source_ids` 和以下 `claim_type`：

- `user_statement`：用户明确陈述。系统拒绝仅用 AI 回复或推测充当用户陈述依据。
- `inference`：Agent 的解释或推测，即使用户批准也保留该类型。
- `conflict`：矛盾或待核实内容，保留不同说法及其时间和出处。

类型校验只是来源约束，不能自动保证结论符合原话；仍需本地用户核对。
现有混合对话导入记录不自动视为用户事实，可先作为推测依据。
更新已有记录需传 `record_id` 和 `expected_revision`，旧来源自动保留，最多 50 个来源 ID。
原文保存与档案结论分开；草稿不进入正式记录，MCP 不提供审核工具。

`processed` 仅表示 Agent 报告已完成该会话当前已保存消息的提取，
不等于草稿批准、所有历史已覆盖或结果正确。新增/修改消息使指纹变化，重新变为待提取。
这是会话级检查点；尚未保存到资料库的消息无法检测，跨会话删除/客户端分支切换不自动镜像。

## 交给其他 Agent 或模型 API 分析

面板“数据分析”选择记录、填写目的，预览后下载 JSON。仅包含选中的记录，
来源 ID 不会自动把未选中的原文加入包。面板最多列出最近 200 条；更多记录可用 MCP/CLI 按 ID 选择。
MCP `prepare_analysis` 同样要求明确的记录 ID，最多 100 条、合计正文最多 1,000,000 字符。

```powershell
personal-os --vault D:\PersonalData\my-vault analysis-pack --ids RECORD_ID_1 RECORD_ID_2 --purpose "分析近期目标与项目" --output D:\PersonalData\analysis.json
```

CLI 默认排除受限资料；明确需要时加 `--allow-restricted`。导出文件必须放在资料库外，
不会覆盖已存在文件。分析包为明文，包含原文、来源和敏感级别。

用户自己的 API 程序读取这个 JSON，选用模型分析即可。框架不保存密钥、不代发请求，
没有开放任意网络可访问的模型 API 代理。面板 HTTP 接口仅供本地面板使用，
外部程序使用 CLI 导出或 MCP；完整的第三方 HTTP API 接入尚未实现。
API 结果可由接入的 Agent 通过 `propose_insight` 提交，并进入同一审核流程。
如果交给云端模型，选中的内容会发送给相应服务商；本地保存不代表模型分析也离线。

## 接力与回退

新增来源字段保存在现有 Markdown 元数据；检查点位于 `.personal-os/extraction/`，完整备份包含它。
老资料库无需迁移。升级前可用完整备份保留状态。v0.3 可读取新增元数据，但没有新工具和面板入口。
测试仅使用虚构资料，未修改用户的实际 Agent 配置、未读取任何真实聊天目录。
