# 记忆有效性、删除与复盘 · v0.5

## 什么可以继续作为依据

记录的可选 memory 字段保存 scope（适用范围）、valid_from/valid_until（带时区的 ISO 日期）、state（active/inactive）。范围是语义说明，不是权限；Agent 需读取范围并判断是否适合当前任务。没有时间字段的旧记录默认不设置时限。

MCP 默认检索、读取、提取来源列表和分析导出拒绝过期、未生效、停用、撤回及证据失效的记录。来源被更新、删除或停用时，关联结论递归退出有效检索。面板仍可显示本地保留的记录和具体状态，供用户复核；不会自动把证据更新后的旧结论重新启用。应重新提交有最新来源版本的草稿，由用户审核。

源资料的历史保留不等于可以继续让 Agent 引用。没有向量检索，当前也没有 embedding 索引可清理。

## 删除的三种方式

记录详情中先“查看删除影响”，再选择处理方式：

- 仅移除原文：保留可恢复历史及本地派生记录，派生结论因失去证据退出 Agent 读取；关联待确认草稿失效。
- 移除并停用：在上项基础上，把关联记录明确设为停用，避免恢复原文后直接再使用。
- 永久清理：沿 source_ids 递归清理原文、派生记录、关联草稿和这些记录的本地历史，并移除相关提取检查点。连历史版本中的来源引用也纳入影响预览，宁可要求用户确认更多关联记录，也不遗漏旧派生内容。

删除需要当前版本及影响指纹。预览后出现新关联或版本变化时，拒绝删除并要求重新预览。永久清理保留无正文的撤回标记和变更通知，阻止在本库通过历史恢复被清理的 ID；不承诺磁盘安全擦除。库中多文件处理不是数据库事务；中断时撤回标记优先阻止有效读取，用户需检查完成情况。

面板删除后清空本项目的进程导入预览和界面分析预览；在途导入预览会被拒绝。CLI 删除不会通知另一个已运行面板进程的内存预览，请用面板删除，或在 CLI 操作后重启所有面板。直接编辑/删除 Markdown 不产生可靠的变更通知。

不清理：外部 Agent 已读入上下文、第三方缓存、独立导出文件、旧备份、云端同步副本或供应商留存。这些必须在对应软件处理；恢复旧备份也可能重新引入已删除内容。自由文字未声明 source_ids 的复制内容无法自动归因。

CLI 可用 deletion-preview ID 获取影响指纹；delete ID --revision N --mode purge --impact FINGERPRINT 进行用户明确确认的本地清理。普通 delete 保持移除原文、保留历史的行为。

## Agent 如何同步

新增 MCP get_memory_changes(after_sequence=0)。每页最多扫描 100 条通知，返回 cursor 和 has_more；Agent 保存游标，继续拉取至 has_more=false，并清除更新、撤回及证据失效 ID 的自身缓存，再读取有效资料。默认隐藏受限记录 ID，通知没有正文。

它是拉取协议，不会主动控制外部软件。Agent 必须遵循协议；每次任务还应重新读取要使用的记录，或自行检查有效期，因为时间到期本身不会产生写入事件。游标只适用于同一资料库，不应跨库复制；切换库/恢复备份后从 0 开始。

## 冲突与决策

冲突草稿展示旧记录、新内容、记录时间、适用范围及来源。批准时必须明确选择替换、并存或按范围保留；并存/按范围保留会创建独立记录，旧记录和版本不会覆盖。拒绝也可保留旧结论。裁决后仍保留 conflict 类型与 resolution，不把它伪装成用户原话。按范围选项要求填写新范围，用户也需核对旧结论范围是否足够明确。

decision 的 memory 可包含 rationale（当时理由）、conditions（当时条件）、expected_outcome（当时预期）、actual_outcome（后续结果）与 reviewed_at。面板录入决策时可填写前三项，详情中补记实际结果。首次填写后的理由、条件和预期不能通过复盘或提案改写，修正应另建记录保留出处。版本历史仍记录每次复盘，避免用事后解释覆盖当时判断。
